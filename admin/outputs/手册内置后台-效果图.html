3三种做法对比
核心差别只有一条：改完手册之后，需不需要我去改代码、重新部署。
做法怎么维护系统改了以后评价
A · 静态子页 把现成的 HTML 与图片搬进 admin/，菜单加一项用 iframe 打开 要我改 HTML / 重拍截图 / 重新部署，通常 1~2 天 不满足“同步”
B · 正文入库 + 后台编辑 手册按章节存进数据库，后台直接改文字、换截图，保存即生效 登录后台自己改，几分钟完成，不需要我介入 ✅ 推荐
C · 自动重拍截图 服务器定时用无头浏览器拍后台界面，自动写回手册 理论全自动，但服务器要装浏览器，且拍出来的是空数据后台 不建议 性价比低
4方案 B 的落地清单
改动集中在后台，前台网站与现有业务功能完全不动，出问题可以单独撤销。

6docs/manual/保留作为「离线 / 打印版」，不删；后台版成为主入口
关于权限：手册对所有登录用户开放查阅（普通编辑员也能看）；只有「超级管理员」和「编辑员」能改内容，与现有其他模块的权限规则一致，不需要新增权限项。
关于“同步”的实话：只要后台界面改版，截图还是需要有人重拍一次 —— 这件事没有可靠的全自动办法。方案 B 能保证的是：重拍后由你自己在后台替换，5 分钟搞定，不用等版本。我另外会给一个「一键重拍全部截图」的脚本，省掉手工截图的活。
5我建议的分步执行
  • 第一步（先可用）：做第 1~4 项 + 只迁移前 5 章，你登录后台点一遍，确认版式与操作手感没问题。
  • 第二步：迁移剩下的章节与全部 32 张图。
  • 第三步（可选）：加「历史版本」——手册改错能回退上一版。
不动的东西：前台网站（site/）一行不改；现有后台的菜单、页面、接口全部保持原样，只新增不修改；数据库只新增一张表，不动任何现有表。
