5两个修复方案（建议都做，各管一层）

A · 前端兜底给卡片图加 object-fit:cover —— 一行 CSS，立即生效

原站 CSS 对 .c-card__image img 本来就没有 object-fit（原站图都是预裁好的，不需要）。我们加了兜底后就再也不会出现拉伸/留白，无论封面是什么比例。

.c-card__image img { object-fit: cover; object-position: 50% 50%; }
  • 覆盖 2 个列表页：site/personal-care/get-inspired/articles.html、site/pharmaceuticals/learn-more/hot-topics.html
  • 对已经正确的 369×208 卡片图零影响（比例相同，裁切无感）
  • 改完立刻解决现在这 5 条，不需要重新导入
注意：cover 是「居中裁切」。对 1041 这种「主体偏右、左侧大留白」的横幅，居中裁切会切到脸的一部分。可选做法：默认 50% 50%，必要时对个别文章用 object-position:62% 50% 把主体推回画面。这只影响观感，不影响是否留白。

B · 导入器治本候选列表页补上「子列表页」

在 R7 的候选数组里，把父目录下的 /articles 与 /hot-topics 也纳入抓取，命中顺序仍是「落地页 → 子列表页 → 历史兼容入口」。

const segs = selfPathTmp.split('/').filter(Boolean);
if (segs.length > 1) {
  const parent = '/' + segs.slice(0, -1).join('/');
  listingCandidates.push(parent);              // 落地页（精选 3 张）
  listingCandidates.push(parent + '/articles');    // ← 新增：完整文章列表
  listingCandidates.push(parent + '/hot-topics');  // ← 新增：完整热点话题
}
  • 2 个文件同步改：backend/src/controllers/import.controller.ts（L399-402）+ backend/src/utils/import-verify.ts（L268-271）
  • fetchText 对非 200 直接 reject → 404 子页会自动跳过，不会污染结果
  • 只对新导入生效；存量 5 条要跑一次校验/修复路径来重抓
为什么建议两个都做：A 是「视觉永不崩」的兜底（成本 1 行，永久有效）；B 是「拿到原生 369×208 卡片图」的治本（画质最好、构图完整）。只做 A → 横幅被裁切，可能切到主体；只做 B → 原站页面结构一改又会回退，前端没有兜底照样崩。
