字数约 380 字，按 edge-tts 中文女声 +8% 语速（实测约 4.3 字/秒）估算旁白净时长约 88 秒，加上留白与纯画面段，成片约 150 秒。最终时长以配音实测为准——先定音、后定帧，顺序不反。

四、技术路线

4.1 三条路线对比

路线做法优点缺点结论
A 逐帧渲染 舞台页写成纯函数 renderAt(t)，按 t 逐帧截图再编码（上一版用的） 帧精确、零抖动、可无损重录、任何一帧都能重出 与异步动画冲突：中台原型里的进度条/下发状态由 setTimeout 驱动，不受时间轴控制，抓到的可能是中间态且每次不同 部分适用
B 分段录屏 每一幕单独用 CDP 录屏（真实点击），按旁白实测时长后期配速，再拼接 异步动画自然播放；单幕可重录（改哪幕录哪幕）；贴合「分段分镜再集合」的思路 帧率不稳需重采样；需隐藏鼠标痕迹；配速靠后期变速 推荐
C 混合 片头/结尾/数据卡（纯 CSS 动画）走 A 逐帧；界面操作段落走 B 录屏；统一 30fps 后拼接 兼顾画面干净度与异步动画的真实性；改动量最小 两套素材需统一色彩与节奏 采用

推荐按路线 C 执行：片头卡与结尾卡共 2 幕用逐帧渲染（这两幕无异步依赖，最能出质感）；其余 8 幕用分段录屏（真实操作，异步动画自然）。这样既不用为了配速去改造刚完成的原型，也保住了首尾的干净度。

4.2 制作流程图

① 定文案 → storyboard.json（10 幕：旁白 + 画面说明）
② 定音 → edge-tts 逐句合成 → 逐句量真实时长 → 回填分镜时长
③ 录画面 → 起本地静态服务 → 逐幕录屏（真实点击，含异步动画）→ 得到 clips/sN.mp4
④ 配速 → 每段按旁白时长变速（系数控制 0.9–1.1）→ 统一 1920×1080 / 30fps
⑤ 拼接合成 → ffmpeg concat 10 段 → 混音（adelay + amix + loudnorm）→ 硬字幕
⑥ 验收 → 抽帧对位（每一幕起点画面与分镜表一致）+ 逐段验电平（每句旁白都有声）+ 无黑帧白屏

4.3 关键技术点

  • 同源服务：这次演示对象是单文件自包含的中台原型，起一个静态服务（python -m http.server）指向 admin/outputs/ 即可，不需要启动后端——比上一版更简单。
  • 录屏方式：用 Puppeteer 的 CDP Page.startScreencast 抓帧（比整屏录制清晰、无窗口边框），或按 30fps 定时截图。中台原型的动画节奏是已知的（进度 420ms×8、校验 500ms×3、分发 620ms×5），可以据此预估每段原始时长。
  • 隐藏演示痕迹：原型底部的「交互演示」提示条与 toast 弹泡在录屏时需注入 CSS 隐藏（舞台层统一处理），避免成片里出现调试信息。
  • 画面质感：1920×1080 下原型是 1440 宽的布局，会用 deviceScaleFactor 缩放策略或视口调整保证不留大片空白；界面在 1080p 里保留安全边距，配合淡入淡出与轻微推近（transform: scale）避免「死画面」。
  • 字幕：中文硬字幕压底部安全区，每句不超过 20 字，与旁白同步。

为什么剪映的 ffmpeg 不能用：实测其编译参数含 --disable-ffprobe（无法量取音频时长，而「先定音后定帧」整套流程依赖它）且编码器列表中没有 libx264（无法输出 H.264）。虽然它有 adelay / amix / loudnorm 滤镜，但缺前两项就不可用。最终解法：安装 PyPI 的 imageio-ffmpeg（自带完整静态构建），不污染系统环境，也不依赖 GitHub 下载。
过程中修掉的一个真缺陷：样片首帧渲染出来全黑。原因是淡入遮罩的归一化写反了（seg(t,-0.6,0) 在 t≥0 时恒等于 1，黑色遮罩一直盖在画面上）。修正为 1 - seg(t,0,0.6) 后正常。这类问题只有抽帧亲眼核对才能发现——码率从 17 kb/s 涨到 337 kb/s 就是最直接的证据。

七、风险与对策

#风险等级对策
1原型的异步动画（进度条、状态流转）与逐帧渲染不兼容，易抓到中间态高已通过路线 C 规避：这些段落走分段录屏，动画按真实节奏播放，不再逐帧抓取
2录屏帧率不稳，成片可能有轻微顿挫中统一重采样到 30fps；关键动作用「停留 + 轻微推近」替代快速运动
3配音时长与画面不匹配（旁白长了画面不够、短了画面空转）中严格「先定音后定帧」；每段按实测时长配速，系数限制在 0.9–1.1 防止变速痕迹
4150 秒偏长，客户可能看不完中同步产出 60 秒精华版用于微信传播；主片用于会议与官网
5成片里露出调试信息（演示提示条、toast、Credit 数字跳变）低舞台层注入 CSS 隐藏提示条；录制时避开 toast 弹出的瞬间
6旁白数字被读错低旁白稿一律用中文数字或不写具体数字；画面承担精确数字

九、待确认项

开拍前需要你确认四件事：
  1. 时长——按 150 秒主片 + 60 秒精华版出，还是只做其中一版？
  2. 旁白口吻——现在这版是「对客户说话」（销售口吻）。如果要一版「对合作方说话」的（强调通道分账、零获客成本），需要换 s2/s3/s9 三句。
  3. 是否露出真实客户名——分镜里用了「客户B / 客户C」占位。若视频要外发，建议保持占位；若只内部看，可换成真实名称。
  4. 要不要竖屏版——竖屏版需要舞台页重新适配画幅，增加约 1 小时。
