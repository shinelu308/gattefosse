新建文章排版编辑优化 · 方案与视觉预览

客户反馈：新建文章只能用一个富文本编辑器排版，自由度不够、不好用、对小白不友好。本页给出三个方案的成本对比、推荐方案的完整交互预览与落地清单 —— 仅为效果图，未动任何真实代码。

核心思路：把「写文章」变成「搭积木」—— 块搭好后保存成官网原版式 HTML，前台零改动

1、客户痛点拆解

三条反馈对应三个结构性缺陷
「自由度不够」富文本只有一种「连续文本流」结构，官网的图文两列 / 引用 / 重点块 / CTA 按钮等版式完全搭不出来
「使用度不够简单」Quill 工具栏 14+ 按钮 + 附加区块另一套入口：两套系统、位置割裂，小白不知道从哪下手
「对小白不友好」排出来的内容与官网版式对不上（class 完全不同），前台观感失控；且新建文章用不了「预览编辑」

2、三个方案

成本并排 —— 用户看的其实是成本，不是创意
维度方案 A · Quill 减法（克制版）方案 B · 块搭建器推荐方案 C · Notion 式斜杠命令
一句话精简 Quill 工具栏 + 几个「插入排版块」按钮模板起步 + 左列搭块 + 右列实时预览，保存拼成官网版式正文里输入 / 唤出块菜单，原位插入
小白友好度中 仍要自己把握整体结构高 所见即所得，填空式创作中高 要记住 / 命令
版式还原低 Quill 产出与官网 class 对不上高 直接用官网 paragraph class 拼装中 取决于插入器实现
改动面小：改工具栏配置 + 1 个插入弹层中：builder 视图 + 拼装/反解析模块；后端与前台零改动大：光标定位、块菜单、键盘交互全要自研
风险低低～中（拼装器要配单测；有预览编辑兜底）高

为什么不开放自由取色 / 任意字号 / 字体选择？原站的文字颜色全部由主题决定（标题品红 #C4004D、链接 #910039、正文 #3C4248），字号是固定梯度（48/40/33/20/13/12px），全站只有一种品牌字体 —— 选项就 4 个颜色 + 3 档字号，小白点选即可，永远不会把页面做花；这些值与原站逐字一致，前台观感 1:1。自由取色器看似「自由度高」，实际是把设计责任推给不会设计的人。

10、我的建议

✅ 建议这样做

  • 第一期：10 种块 + 3 个模板（产品故事 / 新闻动态 / 活动回顾）+ 拼 contentHtml —— 后端、前台零改动，风险最小
  • 第二期（可选）：反解析回块 + 块结构持久化；再补 key-figures（数字组）、accordeon（折叠）两种块
  • 新建文章默认进块搭建；已有原站内容的文章维持「预览编辑」默认，互不干扰
  • 块内迷你编辑器只留 B I U 链接 列表 清格式 六个键

⚠️ 刻意不做

  • Notion 式 / 斜杠命令（方案 C）：自由度最高，但快捷键与输入习惯对小白反而是新的学习成本，且实现复杂度大 —— 不符合「简单」这个目标
  • 自由拖拽排序：↑↓ 按钮已够用；HTML5 拖拽在 iframe/触屏上坑多，收益低
  • 块类型贪多：库里 15 种段落类型，10 种已覆盖 98% 使用；剩下（cartography 地图 / key-figures-carousel 等）等真实需求出现再加
  • 不要碰已有文章的默认模式：原站导入内容仍是「预览编辑」，避免两种心智并存
  • 不开放自由取色 / 任意字号 / 字体选择：全部收敛为原站已有形态的预设变体（见第 7 节），防止把页面做花
