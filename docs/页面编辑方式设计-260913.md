# 页面编辑方式设计（站点内容 · 31 页）

日期：2026-09-13
问题：站点内容这块板块，页面编辑方式该怎么设计，才能前后端数据互通、小白用户改起来容易？
配套文档：`docs/页面区块化方案-260912.md`（讲区块化架构与三档路线）

---

## 一、结论

**不要把小白用户丢进「区块类型」和「HTML 源码」里。让他直接在真实页面上点。**

设计成三档模式，第一档做默认：

| 模式 | 给谁用 | 能干什么 | 界面形态 |
|---|---|---|---|
| **预览编辑**（默认） | 小白 90% 的日常 | 点文字改文字、点图片换图、点视频换链接 | 真实页面 iframe + 顶部悬浮条 |
| **区块编辑** | 要增删区块 / 调顺序 | 加一段文字、加一组卡片、上下移、删除 | 现有 10 种区块表单 |
| **高级设置** | 只给超级管理员 | 页面标识、前端路径、HTML 源码、删除页面 | 折叠收纳 |

并且加**一条互斥规则**（见第四节）——这是整个设计里最关键的一笔。

---

## 二、为什么敢这么做：基建已经在仓库里了

这套「点哪改哪」不是要新造，文章编辑器**已经跑通了**，而且和文章没有实质耦合。

### 2.1 iframe 内脚本（`admin/preview-inline-<日期>.js`）

> 当前在用：`admin/preview-inline-261010.js`。改内容必须**改文件名**击穿缓存，并同步
> `admin/index.html`（2 处）与 `admin/learn-more-standalone.html`（1 处）的引用。

只依赖两样东西：

- 一个 root 容器 `#cp-root`
- 容器内的 `text 节点` / `IMG` / `IFRAME` / `VIDEO` / `A`（链接，2026-10-10 新增）

补丁路径是「从 `#cp-root` 到目标节点的 childNodes 索引链，每步带 nodeName」。**跟文章没关系**——换成页面的 `contentHtml` 一样跑。

它还自带视频链接解析器，已支持 YouTube / 哔哩哔哩 / 腾讯视频 / 优酷（含 BV 号、av 号、`v.qq.com/x/cover/…` 三种入参形态）。这套解析器做区块编辑的「视频」字段时可以直接复用。

### 2.2 后端回填（`backend/src/utils/content-patch.ts`，5.7 KB）

```ts
export function applyContentPatches(html: string, patches: ContentPatch[]): ApplyPatchesResult
// → { html, applied, failed: [{ index, reason }] }
```

**纯函数**。内部自己建 `#__cp-root` 包住传进来的 HTML，用 jsdom 按路径原位回填，class / 结构 / 属性一个不动。逐补丁校验旧值，**任何一处失败就整批不落库**。零业务耦合。

### 2.3 文章侧的完整链路（可直接照抄）

| 环节 | 位置 |
|---|---|
| 三模式切换按钮 + 预览工具条 | `admin/index.html` 2915-2933 行 |
| 模式状态与互斥提示 | 7588-7616 行（`articleContentMode`、`articleContentLocked`） |
| `buildPreviewDoc()` / `openArticlePreview()` / `handlePreviewMessage()` / `savePreviewPatches()` | 7714-7809 行 |
| 后端回填接口 | `POST /api/news/:id/content-patches` → `applyContentPatchesHandler`（`news.controller.ts`） |

其中 `articleContentLocked` 的既有逻辑正好是同一个思路：**原站导入的内容锁死预览编辑，禁用可视化编辑（会破坏版式）**。页面这套照搬即可。

### 2.4 页面侧要新增的，就这么点

- `backend/src/controllers/content.controller.ts`：加 `applyPageContentPatchesHandler`（约 25 行，复用 `applyContentPatches`）
- `backend/src/routes/content.routes.ts`：加 1 行路由
- `admin/index.html`：页面编辑页的三模式改动 + 页面版 `buildPreviewDoc()`

## 三、三档模式定义

### 模式 1｜预览编辑（默认）

- 在 iframe 里加载**真实页面**（前台 CSS + 该页 `contentHtml` + `#cp-root` 容器）
- 点文字 → 弹小浮层改文字；点图片 → 上传/替换；点视频 → 粘贴链接自动识别
- 顶部工具条：`已修改 N 处，未保存` / `保存修改` / `放弃修改`
- 底部说明：**结构与版式锁定，改不坏；修改直接入库，不用再点页面底部「保存」**
- 小白需要的词汇全部收起：不出现 `pageKey`、`slug`、`contentHtml`、`blockType`

### 模式 2｜区块编辑

- 保留现有 10 种区块（头部横幅 / 标语 / 双主题 / 特征卡片 / 产品推广 / 统计数据 / 文本 / 三卡片 / 双CTA / 引语）
- 用于**结构性调整**：加区块、删区块、上下移、改卡片数量
- 字段要做小白化（见第六节）

### 模式 3｜高级设置

- 页面标识、前端路径：**只读展示**（用灰底说明「系统内部用，正常不用改」）
- HTML 源码：默认折叠，按角色限制（`super_admin`）
- 删除页面：单独的危险区

## 四、一条互斥规则（本设计的核心）

`page_contents` 里 `content`（区块数组）和 `content_html`（整段 HTML）**都往页面同一处渲染**。同时存在时必然有一个永远不生效——**这正是现在 23 页的隐性 bug**：26 页的 JSON 里躺着一个 hero 区块，前端 23 页根本不读它。

所以必须定死：

```
一页二选一
  ├─ 有正文 HTML  →  预览编辑（版式锁定，保真）
  └─ 无正文 HTML  →  区块编辑（自由搭，真·全动态）
```

**落到 31 页的现状**：

- 23 页「hero 区块 + 正文 HTML」 → 默认进**预览编辑**
- 3 页（home / personal-care / pharmaceuticals）区块已接通 → 走**区块编辑**
- 5 页（markets / legal-notice / terms-and-conditions / personal-data-policy / sitemap）只有 HTML → **预览编辑**
- **新增页面** → 天然没有 HTML，走**区块编辑**（真正「全动态」）

切模式时给明确提示，并保留原内容备份可还原：

> 此页正文目前是 HTML 形式。切到区块编辑会替换现有正文，原内容自动备份可还原

## 五、前后端数据互通设计

### 读

| 用途 | 接口 | 状态 |
|---|---|---|
| 取页面内容 | `GET /api/content/pages/:pageKey` | 已存在（公开） |
| 管理端列表 | `GET /api/content/admin/pages` | 已存在 |

前端渲染规则：

```
blocks 数组非空  →  逐块按 type 渲染
blocks 为空      →  回落 v-html(contentHtml)
```

### 写（三条通道，各管一段，互不越界）

| 通道 | 接口 | 只动哪个字段 | 谁在用 |
|---|---|---|---|
| 基本信息 | `PUT /api/content/admin/pages/:pageKey` | `title` / `slug` / `meta*` | 高级设置 |
| 区块 | 同上（带 `content` 数组） | `content` | 区块编辑 |
| 原位补丁 | **新增** `POST /api/content/admin/pages/:pageKey/content-patches` | **只动 `content_html`** | 预览编辑 |

原位补丁走的是和文章完全一样的 `applyContentPatches(html, patches)`：路径定位 + 旧值校验，**任何一处失败整批不落库**并返回失败明细。

## 八、风险与注意

1. **预览编辑的 CSS 要按页面对**。文章版 `buildPreviewDoc()` 写死了 6 个 CSS（5 个 Drupal 聚合 + 1 个文章渲染）。页面类型多，CSS 列表要按页面归类准备，否则预览和实际长得不一样——**预览不像真页面，小白会更慌**。
2. **`themeClass` 页面没有**。文章用 `themeClass`（`theme-cosm` 红 / `theme-pharma` 蓝）控制 `--accent-color`。页面表无此字段，要么补一列（ALTER TABLE），要么按 pageKey 在前端映射。
3. **不要两模式并行编辑同一页**。互斥规则必须真的拦住，不能只靠文案提示。
4. **`content` / `content_html` 的优先级要先定死再上线**，否则会出现「后台以为清空了、前台还在显示老内容」。
5. **后台文案与代码不一致**（`admin/index.html` 4230 行 vs 8437-8443 行），一并对齐。

## 九、后续扩展（2026-10-10）：链接 href 补丁

**触发**：正文里大量「文字挂链接跳第三级页面」（产品详情 / 栏目页），小白在编辑视图里点这类
文字只能改文字、改不了跳转地址。

**根因**：`hitTarget()` 只有 IMG / IFRAME / 其余走 text 三个分支 → `<a>` 一律落到 text 分支。

**补丁类型从 3 类扩到 4 类**：`text` / `img` / `video` / **`link`**。

### 设计要点（再扩展时照抄这套判断）

1. **命中优先级**：`IMG` / `IFRAME` → **`A`** → `text`。
   - 排在 IMG/IFRAME **之后**：`<a><img></a>`（colorbox 灯箱图、可点击横幅）点图仍优先「替换图片」，
     外层链接改走**图片浮层里的次级入口**（`#cp-img-to-link`）。抢在 IMG 前面会让换图能力消失。
   - 排在 text **之前**：否则永远弹「修改文字」，href 无从修改 —— 这正是本次缺陷。
2. **一个浮层同时改两件事**：`editLink()` 给「链接地址 + 显示文字」双字段。
   - 地址 → 新增 `link` 补丁；文字 → **既有 `text` 补丁**（后端零新增负担）。
   - 「显示文字」框按**点击落点**定位文本节点（`anchorTextTarget` 用 `caretRangeFromPoint`）；
     落点拿不到就退回 `soleTextNode()`（`<a>` 内恰好一个非空文本节点时）。
     于是 `<a><div>标题</div><div>描述</div></a>` 点标题 → 只改标题，**与旧版行为一致，不退化**；
     纯图链接（0 个文本节点）→ 不给文字框，只提示可改地址。
3. **地址留空 = 取消链接**（`removeAttribute('href')`）。顺带修好了 sitemap 里 3 个导入时
   丢了 href 的 `<a><span>给药途径</span></a>` —— 现在可以补回。
4. **白名单前后端逐字一致**（前端即时反馈 / 后端防绕过，语义不得漂移）：

   ```js
   /^(?:\/(?!\/)[^\s"'<>\\]*|https?:\/\/[^\s"'<>\\]+|#[^\s"'<>\\]*)$/i
   ```

   放行 `/站内路径`（`//host` 协议相对**拒**）、`https://完整地址`、`#页内锚点`；
   `javascript:` / `data:` / `vbscript:` / 含空白或引号的值天然被拒。

### 易漏点（下次扩展同类补丁时逐条对）

- **宿主页不止一个**：除了 `admin/index.html`（文章 + 页面两条 `handlePreviewMessage`），
  还有 `admin/learn-more-standalone.html`（药用辅料文章子页）。三处都要放行新的 `kind`。
- **改内容必改名**：脚本名带日期，改完要同步**全部**引用（含注释里的）。
- **混合换行的文件**：`admin/index.html` 是全 CRLF，`admin/learn-more-standalone.html` 是
  **CRLF + LF 混合**。补丁脚本一律**只做行内字符串替换**，不要拼多行锚点，否则会把换行符洗掉。
- **测试断言易错**：浏览器会把 `#D97706` 规范化成 `rgb(217, 119, 6)`；纯空白输入走的是
  「取消链接」分支（合法）而不是「非法值」。
- **点视口外的元素**：预览正文很长，手算坐标会点到视口外（假失败）。用 frame 的
  ElementHandle + `boundingBox()`，让 puppeteer 自己滚。
