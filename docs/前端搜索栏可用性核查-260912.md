# 前端搜索栏可用性核查 · 2026-09-12

**一句话结论**：搜索栏**能搜出东西**（入口、弹窗、提交、结果渲染全通），
但**搜索之后的三个动作全是坏的**——点侧栏筛选结果清空、点排序没反应、结果总数是假的；
且药用辅料产品在热门词下**永远搜不到**。

## 二、问题清单

### 🔴 P0 · 点侧栏筛选 → 结果全部清空

- **现象**：搜出 20 项后，点左侧任一筛选（如「ADDIAACTIVE : 个人护理 (9)」），页面变 **0 项搜索结果**、
  关键词输入框清空、卡片全没了。
- **证据**：`search.html?keyword=Gatuline` → 点筛选 → URL 变 `search.html?type=5&i=1`（**keyword 丢了**）→ `total=0, cards=0`。
  截图 `admin/outputs/search-facet-empty.png`。
- **根因**：facet 链接是**静态导出时硬编码**的 `href="search.html?type=5&i=1"`，不带当前 `keyword`；
  而 `getAllContentList()` 开头 `if (!w) { total=0; return }` 直接早返回。
- **修复方向**：渲染时给 facet href 拼上当前 query（`keyword` / `page` / `order`），
  或改为 `@click.prevent` 走 `setUrlParam()` 改写 URL 而不是跳转。

### 🔴 P1 · 侧栏筛选本身没有过滤逻辑（15 个筛选全是装饰）

- **证据**：`/api/search?keyword=Gatuline&type=9` 与 `/api/search?keyword=Gatuline` 返回**完全相同**。
- **根因**：两端都没接。
  - 前端：`atype / goodsCategoryId / catId` 读出来了，但 `GatteAPI.Search.all(w)` **只传 keyword**。
  - 后端：`search.controller.ts` 解构了 `type`，**从未使用**。
- **影响**：新闻 / 活动 / 研讨会 / 出版物 / 手册 / 热点话题 / 配方 / 成分 / 产品 / 分公司… 这些分类点了一律无效。

### 🟠 P1 · 结果总数是假的，且药用辅料会被挤掉

- **证据 A（总数随 limit 变）**：`limit=10` → `total=20`；`limit=50` → `total=32`。
  说明 `total` 是**截断后的条数**，不是数据库真实命中数。页面上的「20 项」是错的。
- **证据 B（pharma 被挤掉）**：搜「和」（PC 命中多）→ `pc:10, pharma:0`；搜 `Gatuline` → `pc:10, pharma:0`。
- **根因**：`search.controller.ts` 第 50-53 行
  ```ts
  const products = [...pcProducts, ...pharmaProducts].slice(0, limitNum);  // ← PC 先入队，pharma 被砍
  ...
  results.total = products.length + news.length + formulations.length;     // ← 用截断后的长度当总数
  ```
- **影响**：只要 PC 命中 ≥10 条，**药用辅料产品在搜索结果里永远不出现**；
  且「N 项搜索结果」永远 ≤ 3×limit（默认 30）。

### 🟠 P2 · 分页越界 + 假分页

- **证据**：`?keyword=Gatuline&page=5` → 分页器显示「**5/3**」且 0 张卡片（无越界钳制）。
- **根因**：分页全在前端做（`allItems.slice(start, start+9)`），而后端每类最多给 10 条、
  `products` 再被砍一次 → 实际最多 30 条可翻，翻不到真实更深的结果。

### 🟡 P2 · 0 结果没有任何空态提示

- **证据**：`?keyword=zzzznope` 页面文本只有「0 项搜索结果 排序 排序 A-Z Z-A」，
  匹配 `/没有|未找到|无结果|换个|试试|no result/` 全部为 false。截图 `admin/outputs/search-zero-result.png`。

### 🟡 P2 · 排序下拉点了没反应

- **证据**：`.js-order-by` 元素 `inForm: false`（不在表单内）、jQuery 事件表为空 `[]`；
  选 A-Z 后 URL 与结果顺序**均无变化**。
- **根因**：`<select name="sort_order">` 在 `.c-search-result` 里，**不在 form 内**；
  页面 JS 读的是 `params.get('order')`（名字都对不上），且 `desc` 变量从未参与查询。

### 🟢 P3 · 「选择内容分类」单选只存在于孤儿文件

- **证据**：真实弹窗实测 `hasTypeRadios: false`（8 个页面全无）。
  只有 `site/search-dialog.html` 里有那组 `apple/orange/banana/grape/brochures` 单选，
  而该文件**全站 0 处引用**（没有任何页面 `.load('/search-dialog.html')`）→ 孤儿文件。
- **副作用**：它里面的 `searchType` 参数（news/goods/articles/Publications/brochures）
  即便提交也不会被 `search.html` 使用——`search.html` 只认 `type`。
- **另**：该文件里「出版物」标签重复了两次（value 分别是 `Publications` 和 `brochures`），
  且 `id="apple"` 等语义错乱——原站导出残留。

## 四、建议修复顺序

| 优先级 | 事项 | 改动面 |
|---|---|---|
| 1 | facet 链接保留当前 query（P0，一行 `setUrlParam` 或拼接） | 仅 `search.html` 前端 |
| 2 | 后端 `products` 不再提前 slice；`total` 用数据库真实 count | `search.controller.ts` |
| 3 | 前端把 `type/i/catId/page/order` 传给接口；后端按 `type` 过滤 | 两端各一处 |
| 4 | 分页钳制 + 后端真分页（offset/limit） | `search.controller.ts` + 前端 |
| 5 | 0 结果空态文案 | 仅前端 |
| 6 | 排序接进查询（或直接隐藏该下拉） | 两端各一处 |
| 7 | 删除孤儿 `site/search-dialog.html`；弹窗如需要分类单选再补 | 前端 |

⚠️ 一并说明：`total` 与「被浏览覆盖率」无关，是**独立缺陷**，别和 `page_views` 口径混在一起改。
