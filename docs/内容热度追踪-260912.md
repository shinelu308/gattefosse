# 内容热度追踪（content_views）· 2026-09-12

> 背景：原先只有「热门页面（按 URL 聚合）」——`page_views.path` 是**去掉 query** 的路径，
> 57 个个人护理产品、54 个药用辅料、99 个配方的详情页在库里全压成**各自一条**，
> 资料（PDF）更是走静态/中转直链，完全收不到。
> 因此无法回答营销真正关心的问题：**哪个产品被看得多、哪份资料被打开得多。**

本功能新增一条**独立于 page_views 的业务对象口径**采集链路，回答对象级热度问题。

---

## 一、两个口径的分工（不要混用）

| | `page_views` | `content_views` |
|---|---|---|
| 口径 | 流量口径 | 业务对象口径 |
| 维度 | 页面路径（去 query） | 对象类型 + 对象 id + 名称快照 |
| 回答 | 今天来了多少人、从哪来 | 哪个产品/资料/文章被看得多 |
| 写入 | `middleware/tracker.ts`（服务端中间件，GET html 自动记） | `POST /api/track/content`（前端 sendBeacon 显式上报） |
| 读取 | `GET /api/stats/overview` | `GET /api/stats/content-heat` |
| 展示 | 后台「总览」页 | 后台「内容热度」页 |

**为什么不合并成一张表**（4 条硬理由，改前必读）：
1. `page_views.path` 是切掉 query 的路径，历史数据**无法回溯**出是哪个产品；
2. 资料（PDF / `/api/documents/:id/download`）不是 html 页面，`tracker.ts` 的 `isPage` 判定直接排除；
3. 产品名称只有前端知道，后端加列只能存 slug/id，产品一改名统计即失真；
4. 混表会让 `page_views` 行数涨一个量级，拖慢现有总览页的内存聚合。

## 二、数据模型 `content_views`

`backend/prisma/schema.prisma` → `model ContentView`

| 列 | 说明 |
|---|---|
| `object_type` | `pc_product` / `formulation` / `pharma_product` / `article` / `news` / `event` / `document` |
| `object_id` | 对象标识（数字 id 或 slug，统一字符串） |
| `object_name` | 对象名称**快照**（对象改名/删除后榜单仍可读） |
| `section` | `personal_care` / `pharma` / `news` / `learn_more` |
| `event_type` | `view`（打开详情页）/ `download`（打开资料） |
| `page_path` | 事件发生所在页面（去 query） |
| `parent_id` / `parent_name` | 资料的归属产品（哪个产品下打开的这份 PDF） |
| `visitor_id` / `ip` / `ua` / `referer` / `region` | 与 page_views 同口径（cookie `__gv`，回退 ip+ua hash） |
| `created_at` | 时间 |

⚠️ **每个字段都要写 `@map("snake_case")`**。漏标一个字段，Prisma 会拿驼峰字段名当物理列名去查库，
报 `P2022: The column ... does not exist`。本表首版就漏了 `objectType/objectId/objectName` 三个。

## 三、采集链路

```
详情页数据加载完成
  → GatteTrack.view(type, id, name, section)      ← site/static/js/track-260912.js
  → 队列合并 700ms → navigator.sendBeacon('/api/track/content', Blob)
  → POST /api/track/content                        ← backend/src/controllers/track.controller.ts
  → 写入 content_views
```

资料（PDF）**不需要改模板**：`track-260912.js` 用 document 级**捕获委托**监听
`.block-files / #product-document / .c-link--document / [data-gt-doc]` 容器内的下载链接，
自动取中文标题（`.c-link__name`）、`data-gt-doc` 标识与当前页对象作为归属。

### 需要接入埋点的页面清单

| 页面 | 调用 |
|---|---|
| `site/personal-care/product-finder/product-detail.html`（PC，`?id=`） | `view('pc_product', product.id, product.name, 'personal_care')` |
| `site/personal-care/formulation-finder/product-detail.html`（`?id=`） | `view('formulation', f.id, f.name, 'personal_care')` |
| `site/pharmaceuticals/product-finder/product-detail.html`（`?slug=`） | `view('pharma_product', product.id, product.name, 'pharma')` |
| `site/news-detail.html`（`?id=`） | 按 `item.type`/`item.category` 映射为 news / event / article |
| `site/personal-care-article-detail.html`（`?id=`） | `view('article', articleId, item.title, 'personal_care')` |
| `site/pharmaceuticals-article-detail.html`（`?id=`） | `view('article', articleId, item.title, 'pharma')` |
| `site/pharmaceuticals/learn-more/{brochures,publications,webinar,hot-topics}.html` | 只需引脚本，下载链接由委托自动追踪 |

调用点一律写成 `if (window.GatteTrack) GatteTrack.view(...)`，脚本缺失时静默降级，不影响业务。

## 四、口径与防刷

- **写入层**（`track.controller.ts`）只挡「爬虫 / 脚本 UA」这一条高置信噪声；
  内网与自测 IP **照写不误** —— 有意的：本地自测能落库，便于验证。
- **展示层**（`content-stats.controller.ts`）走 `utils/visit-filter.ts` 的 `isCountableView()`：
  剔除爬虫 UA / 内网 IP / 自测出口 IP。改白名单只改 `visit-filter.ts`，历史统计立刻跟着变。
- **去重**：同一 `visitorId + objectType + objectId + event` 在 **30 秒**内只落一条（进程级内存 Map）。
- **输入校验**：objectType 走白名单；objectId 禁止空白/斜杠/引号/尖括号/反斜杠，≤120 字符；
  单次请求 ≤20 个事件；`name` ≤200 字符。
- 无 `__gv` cookie 时**在响应头补种**（放在所有早返回之前，避免首次上报被去重时不下发 cookie）。

## 五、后台「内容热度」页

`admin/content-heat-standalone.html`（iframe 子页，入口在侧边栏「总览」下方）

- 时间范围：近 7 / 30 / 90 天 / 全部
- 概要：浏览事件数 / 独立访客 / 被浏览过的对象数
- 板块 Tab：个人护理 / 药用辅料 / 新闻与活动 / 了解更多
- 每个板块下按类型分榜：产品 / 配方 / 资料 / 文章，每行 `名称 + 近 7 天趋势条 + PV · UV + 最近时间`
- 「本期被浏览 N / 共 M 个」覆盖率 + **未被浏览过的对象清单**（营销上要推的就是这些）
- 权限：不做模块映射 → 与「总览」一样对所有登录员工可见（只读统计，接口层仍需 editor 及以上）

| 脚本 | 覆盖 |
|---|---|

⚠️ 两个踩过的坑：
1. **`navigator.sendBeacon` 发 Blob 时，CDP 的 `requestWillBeSent.postData` 为空** ——
   用 `req.postData()` 断言会假失败。改为「操作前后 `max(content_views.id)` 取差集」查库核对。
2. puppeteer headless 的默认 UA 含 `HeadlessChrome`，会被 `isBotUa` 挡掉 —— 测试必须覆盖 UA。

## 七、已知边界

- **历史访问无法回溯**：埋点自上线之日起生效。
- 聚合目前在内存中做（`MAX_ROWS = 50000`）。行数涨到十万级以上应改为 SQL `GROUP BY`，
  或按天物化一张 `content_view_daily`。
- `documents.downloadCount` 与 `content_views` 是两套计数（前者由 `/api/documents/:id/download` 自增），
  暂未合并；资料热度以 `content_views` 为准。
- `site/personal-care/formulation-finder/product-detail-2025-03-28.html`、
  `site/formulation-technologies/caring-patients.html` 两个孤儿页有内联脚本语法错误
  （`check-inline-syntax.js` 改为递归扫描后暴露），均 **0 处引用**，未处理。
